# 1A 第一批：本地可靠性基线

2026-09-07。状态：实现与验证批次，尚未达到公网多用户上线条件。

## 产品验收方向

目标用户是离家求学、不能长期与宠物待在一起的学生。核心验收是用户能认出自己的宠物，并愿意持续让它留在桌面陪伴。当前生图仅输入文字特征，没有把原照片作为生图参考；后续必须用授权宠物照片样本检验身份保真。四种风格、循环动作与收费方式都应服从这个目标。

## 本批交付

- 修复 `/api/archive/[id]` 缺少 GET，成功页可以加载已有档案。
- 修复本地媒体请求固定回连 8080，按实际本地端口或 PORT 解析。
- 复用相同视频时也写回视频模式，避免之前切到静态图片后仍显示旧模式。
- 档案写入使用同目录临时文件、fsync、原子 rename；读取损坏 JSON 明确失败，不把空数组写回覆盖原档案。
- 异步图片下载后重新读取档案，修复同进程并发保存覆盖。
- 单进程动画状态保存到 `data/animation-tasks.json`。重启后保留已完成结果，中断任务标为失败并提示核对上游状态；不会自动重新提交付费任务。
- 两个前端入口共用可取消、有限时、无请求重叠的轮询。任务丢失立即提示，连续三次网络错误停止，等待上限 15 分钟。
- 网页预览与请求打开桌宠使用不同完成文案，不再把网页视频描述为已在桌面出现。
- 固定根项目直接依赖版本，与已有 lock 一致；新增 Node 版本要求、`npm run doctor` 和 `npm run check`。
- 忽略密钥、虚拟环境和生成产物。此前已暂存的 877 项保留原样；忽略规则不会把它们从暂存区移除。

## 下一切片的边界

云端负责用户身份、资产归属、额度、任务提交与查询；任务 worker 负责生成、下载、抠像和结果验收；对象存储保存原图与合格成品；本机 Electron 负责下载授权素材、透明窗口与离线播放。

下一批首先实现 PostgreSQL 数据模型和持久任务 worker，定义 users、pets、assets、generation_jobs、usage_ledger。任务必须记录上游 task ID、幂等键、状态、重试次数和错误；网络超时后先查询原任务，不能盲目重新生成。原图和成品使用私有对象存储与短时授权链接，不能把上游临时链接当永久存储。

然后接入登录和所有读写接口的资源归属校验，最后让发行版 Electron 通过限定 IPC 载入已授权素材。线上账号、数据库、对象存储与付费部署需要用户选择实际服务后才连接；本批没有创建这些外部资源。

## 尚未解决

JSON 快照不是多进程数据库，当前后台任务不是可靠云端队列，不支持多副本或中途自动恢复。账号隔离、额度、私有资产、正版素材/模型商用许可核验、真实循环质量、安装包桌宠能力、付费与退款都未完成。不要将本批推送部署为公开服务。
