# 三画风稳定性：本轮实现与验收

## 范围和边界

保持已验收的 v5 三画风正向模板及现有 Qwen 模型；v6 表示新增分画风负面词与生成策略，不是重新设计画风。恢复水墨、贴纸、像素三个选项，不再默认只生成水墨。不恢复 VL 身份审核，用户仍决定像不像自己的宠物；故事仍只用于档案，不进入生图请求。

## 已实现

- 上传后先确认照片：手动框选目标、旋转、可选亮度微调；展示实际输入预览，方向和最长边 2048 像素规范化。亮度默认不改，避免改变毛色。需要用户确认主角和关键部位。
- 真实解码检查（PNG/JPEG/WebP，静态图，32 像素以上，5MB/24MP 服务端限制）；低分辨率、过暗、低细节等只提示。浏览器先接受不超过 20MB 的原始图片并缩放。不是自动宠物检测，不会修复遮挡或保证识别多只动物。
- 用户可选 1–3 种画风，每风格 1–3 张候选；默认三种各一张。沿用一轮 4 内测点数并按候选数量倍增：1/2/3 张分别预留 4/8/12 点，即使只选一个画风也按一轮计。点数不是供应商人民币费用；生成前明确显示。
- 服务端独占正式模板；特征输入有长度上限，不静默截断用户修正。每个任务冻结模型、提示词版本、正负提示词、画风、候选号和随机种子；同一幂等请求不会重新抽种子。种子用于追溯，不保证云端位级重现。
- 每张图片保存后立即写任务检查点。后一张失败，前面的图片仍能展示并从任务页保存；不自动重做已计费整批。若已有成品，后一张明确拒绝也不自动整单退款，留待核对剩余费用。
- 成品有纯技术提示（近空白、边缘占用等），不调用 VL 判身份，不挡住用户选择或后续视频；不宣称能自动识别多头/多爪。
- 可选四项评分、问题分类及“愿意使用”反馈；只允许本人真实任务的图片，版本来源由数据库关联。评分不代表训练授权；不把个人故事发往绘图模型。
- 评测样本盘点、SHA-256 去重和反馈导出工具；不会自动付费调用模型。

## 如何手动验收

1. 确认 Docker Desktop 已启动；运行 `npm run service:setup` 恢复现有数据库，再运行 `npm run migrate` 和 `npm run dev -- -H 127.0.0.1`。等待终端显示 Ready，打开 <http://127.0.0.1:3000/developer>，点击进入创建页。服务已启动时不要重复启动第二套 Worker。
2. 上传猫或狗的照片，检查整图/框选/旋转后右侧实际输入；确认主角后识别。保留或删除标签，填写自己的外貌修正和故事。
3. 预览档案：应有三个画风复选框，默认全选；选择每风格两张时应显示共六张和八内测点数。需要节约调用时改回每风格一张。
4. 生成后可以选择候选、查看非阻断提示、保存可选反馈。不要为了填测试记录，冒充真实用户提交评分。
5. 去 `/tasks` 核对已保存任务。中途网络异常或部分失败时，不要直接再次付费提交；先查看已完成的结果。

## 评测留到最后

本次本地 Catest 盘点为 9 张去重后的支持格式图片，尚未人工确认分别属于几只宠物；不等同 9 只，更不等于 40 只猫狗。AVIF 未纳入当前上传支持范围。

后续建议准备 20 猫 + 20 狗的独立验收集，覆盖黑/白/长短毛、花纹、体型、正侧面和常见拍摄条件；同一宠物的不同照片必须留在同一数据分组。调参集与验收集分开，冻结参数后才测后者。先取得素材使用许可和付费预算确认。

记录全部请求（含失败），按画风分别统计首张达标率、限定候选数内用户可接受率、实际人民币成本、耗时和失败分类。多候选不是独立抽奖，不能用 `1-(1-p)^n` 当作实测成功率；主动填写的满意度也有选择偏差。几张好图只能证明可达质量，不能据此给出面对任意猫狗的保证概率。

暂不进行付费批量评测、模型横评或微调；目前没有足够的独立测试数据和训练授权来证明它们必要。技术提示无法代替主人肉眼判断，也不代表上线所需的视频/云存储链路已验收。
